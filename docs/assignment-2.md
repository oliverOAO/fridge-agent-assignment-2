# 指定作業 2 冰箱食材與餐食規劃助手

課程 AI Agent　　姓名 ____________　　學號 ____________

本作業接續作業 1，完成以食材庫存為依據的單餐規劃雛形。使用者提供人數、時間、道數與偏好，Agent 查詢實際庫存與食譜，挑出候選菜單後呼叫驗證工具。工具會加總跨菜色用量、檢查時間與缺料，再決定是否產生菜單或採買清單。庫存變更由使用者明確確認，任務狀態採 SQLite 保存。

## Agent 運作方式

```text
使用者輸入 → 取得庫存快照 → 搜尋食譜與排列候選
                          ↓
         規則排序或 Ollama 選擇候選 → 驗證兩道菜總量
                                                    ↓
                       可行菜單／需補貨／無解／錯誤
                          ↓
          使用者確認已完成 → 檢查庫存版本 → 寫入交易
```

作業 2 採用受控的 Tool Use 工作流。離線模式用同一組候選及工具完成流程。Ollama 模式由模型選候選食譜 ID 並回傳 `validate_meal` 工具呼叫，Python 檢查參數與候選後才執行。工具觀察由控制器依固定規則轉成可行結果，模型沒有資料庫寫入權限。每次規劃最多一次模型選擇，模型請求逾時為 60 秒。作業 3 再針對「選到缺料方案」加入有上限的重選，方便實作對照實驗。

## 工具定義

| 工具 | 目的 | 輸入 | 輸出 | 例外處理 |
|---|---|---|---|---|
| `inventory_snapshot` | 取得一致的庫存快照 | 無使用者參數 | 庫存版本、品項、數量、單位 | 資料庫錯誤時回報，停止規劃 |
| `search_recipes` | 排除不合條件的食譜，建立候選 | 排除食材、上限分鐘，控制器另帶入道數、庫存及偏好 | 可配對的食譜與最多八組排序後候選 | 無組合時回傳 `no_candidates` |
| `validate_meal` | 檢查所選食譜及其合計需求 | 食譜 ID、人數，控制器另帶入候選清單、條件與庫存快照 | 食譜明細、總時間、各食材需求量與缺料量 | 錯誤 ID、重複 ID、時間或排除條件違規時拒絕。缺料且禁止採買時回傳 `insufficient_stock` |
| `confirm` | 經使用者確認後扣除菜單用量 | 介面送出的 `meal_id` | 扣除明細及 `confirmed` 或 `already_confirmed` | 庫存版本不同即要求重規劃。交易失敗全部回滾，同一 ID 不會扣兩次 |

`search_recipes` 的搜尋與排序由 `FridgeAgent.search_recipes` 和 `FridgeAgent.candidates` 完成。`inventory_snapshot` 由 `Storage.snapshot` 執行。`validate_meal` 是 Ollama 唯一可呼叫的工具，採買清單由驗證後的缺料量產生。`confirm` 只接受先前保存且可行的菜單 ID。

下表依 [實際離線執行紀錄](evidence/offline-run.json) 摘要。模式為離線規則，資料庫使用獨立的測試庫存。

## 失敗情境與處置

| 案例與實際結果 | 原因 | 系統處置與使用者下一步 |
|---|---|---|
| F01 查無候選，`no_candidates` | 要求 3 分鐘內完成兩道，食譜庫無符合組合 | 停止規劃。可增加時間、減少道數或調整排除條件 |
| F02 庫存不足，`insufficient_stock` | 庫存空白，且使用者禁止採買 | 顯示缺少品項，不建立可扣除菜單。可補登庫存或允許採買 |
| F03 確認被拒絕 | 規劃完成後，使用者另行修改雞蛋數量，菜單的庫存版本已失效 | 保留最新庫存且不扣除。重新規劃後再確認 |

S02 另外驗證允許採買時回傳 `shopping_needed`，並提供缺料清單。六項自動測試覆蓋份量加總、確認與持久化、庫存衝突、時間與排除限制、採買政策，以及模型工具介面回應與錯誤處理。2026 年 11 月 22 日的五個 CLI 展示案例和六項測試均在 Podman 容器通過，網頁表單也通過 Streamlit 操作測試。容器另呼叫 Windows 上實際運行的 Ollama `qwen3:1.7b`，成功完成 S01 的模型選擇及工具驗證，取得兩道菜與 18 分鐘的預估時間。完整觀察與結果可見[容器實跑紀錄](evidence/ollama-podman-run.json)。

## 與作業一的差異

第一版以結構化欄位收集硬性限制。Ollama 可額外根據文字偏好從候選菜單中選擇。已先加入跨菜色總量檢查，確保目前版本不會把共用食材重複算成可用。扣庫存依使用者確認的菜單用量，個別修改實際用量、跨次偏好記憶、食材日期提示及自動重選留待後續擴充。
